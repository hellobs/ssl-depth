# 骨干诊断结果 2026-11-17

## 目的

回答一个问题：**预训练权重对前视深度下游有没有用，用哪一套**。

起因是 `scripts/train_min.py` 第 164 行写的是 `MicroJEPA(cfg)`，没有加载任何权重。
也就是说之前 3 轮和 20 轮的结果，骨干都是随机初始化的 ViT，
不存在预训练这一步。δ1 0.30 是随机 ViT 的上限，不是 JEPA 的上限。

## 方法

编码器全部冻结，只训一个 0.81M 参数的卷积深度头。
除骨干外所有条件相同：同一份 `cache/kept80.json`、同一划分（seed 0 洗牌）、
同一解码器、同一 masked L1 视差损失、同样 15 轮 / batch 16 / lr 1e-3。

输入统一缩放到 192x108。这是两套 JEPA 权重 pos embedding 的网格要求
（patch 6 乘以 32x18 = 576 token）。数据原生 256x256，缩放在五组间同等施加。

| 骨干 | 架构 | 预训练数据 | 方式 |
|---|---|---|---|
| scratch | MicroJEPA ViT | 无 | 随机 |
| jepa | MicroJEPA ViT | VisDrone，真实航拍俯视 | 自监督 4000 步 |
| dronelab | MicroJEPA ViT | dronelab，AirSim 简化场景 | 自监督 8000 步 |
| resnet_scratch | ResNet18 | 无 | 随机 |
| imagenet | ResNet18 | ImageNet | 有监督 |

## 结果

test 只有 3 趟 205 帧，绝对值偏悲观，只看组间排序。

| 骨干 | seed | val AbsRel | val δ1 | test AbsRel | test δ1 |
|---|---|---|---|---|---|
| imagenet | 0 | 0.122 | 0.866 | 0.331 | 0.462 |
| imagenet | 1 | 0.117 | 0.869 | 0.314 | 0.490 |
| resnet_scratch | 0 | 0.246 | 0.791 | 0.812 | 0.349 |
| jepa | 0 | 0.381 | 0.579 | 0.828 | 0.313 |
| jepa | 1 | 0.371 | 0.671 | 0.800 | 0.315 |
| dronelab | 0 | 0.825 | 0.285 | 1.051 | 0.238 |
| scratch | 0 | 0.227 | 0.676 | 0.730 | 0.220 |

种子极差：imagenet 0.028，jepa 0.002。组间差距 0.16，远大于噪声。

## 三条可归因的效应

1. 架构，ViT 换成 CNN，两边都随机：test δ1 0.220 到 0.349，加 0.129
2. 有监督预训练，CNN 内随机换 ImageNet：0.349 到 0.476，加 0.127，val AbsRel 减半
3. 自监督预训练，ViT 内随机换 VisDrone：0.220 到 0.314，加 0.094
4. 同域自监督，ViT 内随机换 dronelab：0.220 到 0.238，加 0.018，等于没有

## 结论

预训练有用，但有监督强于自监督，架构差距不比预训练差距小。
同域但场景过于简单（纯色方块加黑色天空）的预训练几乎零收益，
说明起作用的是场景内容的丰富度，不是视角匹配。

这条与 V-JEPA 2.1（arXiv 2603.14482）的诊断一致：掩码预测目标只监督 masked token，
context token 没有压力保留局部结构，稠密任务特征弱。

## 对 train_min.py 的三条修改

1. 骨干换成 ImageNet ResNet18 加卷积头。当前随机 ViT 的 test δ1 是 0.32，
   换完是 0.47 到 0.49，同样冻结、同样 15 轮。
2. 如果坚持用 MicroJEPA，必须显式加载 `outputs/base_s6/jepa.pt` 或
   `outputs/dl_act8k/jepa.pt`（2026-11-19 已删除，见下），并且 cfg 必须是
   patch 6 / dim 192 / depth 6 / heads 3 / img 108x192，否则形状对不上，加载不了。

   > 2026-11-19 补记：`dl_act8k` 整个目录（707 MB，含 12 个检查点）已按用户要求删除，
   > 它在下游的 δ1 是 0.238 / AbsRel 1.05。本文档保留当时的结论，但权重不再可取。
   > 现在可引用的是域内自监督的 `ssl-depth/runs/jepa_domain_clean/jepa.pt`（δ1 0.829）。
3. 评估协议要改。当前 test 3 趟只来自 2 个 run，保留率 48% 到 51%，
   而全部 22 趟的平均保留率是 76%。test 集系统性偏向深度质量最差的趟，
   val 与 test 的差距不能全部归给过拟合。
