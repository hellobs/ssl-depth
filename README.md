# ssl-depth

低空物流配送无人机的视觉测距误差研究。课程论文项目，配套代码与数据索引。

论文：《基于人工智能的无人机单目深度测距误差研究与设计学分析》

作者：张子睿（华南理工大学设计学院）、盛祺（自动化科学与工程学院）、刘子瑄（电子商务系）、马婧怡（材料科学与工程学院）

## 这个项目在做什么

配送无人机的视觉分支需要从单张图像估计前方障碍的距离。这个估计会出错，而错误不是均匀分布的。项目做四件事：

1. 在仿真城市环境中采集飞行数据，训练单目深度估计模型
2. 固定解码器与训练预算，比较四种视觉表征，并对误差作分层分析
3. 把误差换算成避障决策，定位失效集中的距离区间与偏差方向
4. 从设计学角度分析信息传达的条件，并把人在回路的复核机制做成可运行的原型

## 数据

原始数据不在本仓库，位于本地 `D:/zzr/wmdata/runs`、`runs_batch2`、`runs_batch3`、`runs_batch4`、`runs_nearfield` 与 `D:/zzr/near_out`，共六批。

每帧包含前视 RGB、稠密深度图、深度有效掩码。深度由 Unreal Engine 4 的 AirSim 插件直接渲染输出，单位为米，与图像严格对齐。

清洗规则：有效范围 0.5 至 80 米，帧有效率不低于 50%。18351 帧候选中保留 12647 帧（69%），对应 87 次飞行、104 个航段。被剔除的帧 95% 在 40 米以外的远景。

划分按航段进行：训练 69、验证 14（1641 帧）、测试 15（1685 帧）。

索引在训练完成后重建过一次：补入 9 个近场航段（756 帧），另有 3 个早期航段的原始记录被清理删除。因此索引的 104 段与实验用的 98 段不完全重合，`scripts/task_metric.py --split held` 从 `runs/v4_imagenet/metrics.json` 读取训练时的划分，避免训练帧漏进留出集。

## 运行

环境：`D:/zzr/microwm/.venv`（Python 3.13 + PyTorch 2.9.1 + CUDA 12.8）

```bash
# 重建索引
python scripts/rebuild_index.py

# 训练并评测某一组骨干
python scripts/diag_backbone.py --backbone imagenet --epochs 15

# 误差分层分析
python scripts/analyze_error.py --backbone imagenet

# 避障判据换算（全量 / 仅留出集）
python scripts/task_metric.py
python scripts/task_metric.py --split held

# 带符号偏差
python scripts/diag_bias.py

# 配图
python scripts/plot_figs_v2.py

# 复核原型（本地 8000 端口）
python scripts/review_app.py
```

可用的骨干：`imagenet`、`resnet_scratch`、`jepa`、`jepa_domain`、`scratch`。
其中 `jepa_domain` 指向 `runs/jepa_domain_clean/jepa.pt`（域内自监督，可引用）；早期那版有 episode 级
泄漏，已移到 `runs/_deprecated/jepa_domain_leaky/`，见该目录下的 README。

域内预训练怎么来的：

```bash
# 56 个纯训练 run，4000 步，约 25 分钟（RTX 5060）
python scripts/pretrain_jepa.py --runs <逗号分隔的 56 个后缀> --steps 4000 \
  --batch 16 --workers 4 --out runs/jepa_domain_clean
```

预训练的超参默认值就是下游规格（108×192 / patch 6 / dim 192 / heads 3 / 576 token）。
位置编码是定长相加、不插值，token 数差一个就会在加载时被形状过滤掉且不报错，
所以脚本存盘后会用下游配置做一次 `verify_loadable` 自检。

## 结果

五组表征的对照（留出集 3326 帧）：

| 骨干 | 预训练数据 | 验证集 δ1 | 测试集 δ1 | 测试集 AbsRel |
|---|---|---|---|---|
| ImageNet ResNet18 | ImageNet 有监督 | 0.819 | 0.866 | 0.127 |
| JEPA 自监督（域内） | 本数据 56 个纯训练 run / 65 episode / 11.7k 帧对 | **0.849** | **0.829** | **0.163** |
| ResNet18 随机初始化 | 无 | 0.810 | 0.825 | 0.252 |
| JEPA 自监督（VisDrone） | VisDrone 56 序列 / 24.2k 帧 | 0.727 | 0.743 | 0.369 |
| ViT 随机初始化 | 无 | 0.709 | 0.696 | 0.319 |

任务指标（留出集 3326 帧，阈值 6 / 9 米）：

| 骨干 | 6 米识别率 | 6 米误触发 | 9 米识别率 | 9 米误触发 | 前方距离中位误差 |
|---|---|---|---|---|---|
| JEPA 自监督（域内） | **81.9%** | 28 | **87.3%** | 24 | **0.69 m** |
| ImageNet ResNet18 | 57.4% | **3** | 67.3% | **10** | — |
| JEPA 自监督（VisDrone） | 63.3% | 49 | 74.4% | 55 | — |
| ResNet18 随机初始化 | 100% | 3089 | 100% | 2846 | 退化（恒判近） |
| ViT 随机初始化 | 0% | 0 | 0% | 0 | 退化（恒判远） |

两个指标指向相反方向：δ1 上 ImageNet 仍最高（0.866 对 0.829），但近场召回上域内自监督反超 24 个百分点（6 米 81.9% 对 57.4%），代价是误触发从 3 次升到 28 次（3326 帧里的 0.84%）。对避障而言漏判比误刹危险得多，这个权衡的方向是对的。

注意早期那一版（已移到 `runs/_deprecated/jepa_domain_leaky/`）不能引用：它按 run 名排除测试集，但划分是 episode 级的，14/16 个 test episode 实际进过预训练，验证集 15 个全部进过。可引的是 `runs/jepa_domain_clean`，它只保留不含任何 val/test episode 的 56 个 run。重跑后 δ1 从 0.830 变 0.829、AbsRel 从 0.177 降到 0.163，说明泄漏没有抬高结论，但流程必须按 episode 级切——两版 δ1 只差 0.001，光看数字分辨不出来，只能靠路径防错。

按真值中位距离分档（ImageNet 预训练）：

| 区间 | 帧数 | AbsRel | δ1 | δ1<0.5 占比 |
|---|---|---|---|---|
| 0-10 米 | 408 | 0.354 | 0.719 | 17.6% |
| 10-20 米 | 1157 | 0.131 | 0.868 | 0.0% |
| 20-40 米 | 1055 | 0.110 | 0.859 | 5.8% |
| 40-81 米 | 706 | 0.110 | 0.874 | 0.4% |

9 米判据（留出集）：该触发 480 帧，识别 323 帧（67.3%），漏判 157，误触发 10。放宽到 12 米，识别率 94.2%。

近场偏差是读远：6 至 9 米区间中位 +1.58 米，85% 的帧高估，三分之一高估超过 2 米。

## 复核原型

`scripts/review_app.py` 是一个单页应用，评审者逐帧判断“可信 / 有保留 / 不可信 / 无法判断”，后三项展开按机理分类的理由清单。队列 110 条，由 `build_review_queue.py` 从触发帧中按距离分档抽样生成。

目前已收集 3 名评审的 46 条记录（覆盖 38 个样本，平均 5.8 秒/条），规模仅够试点。结构化理由的填写率只有 4%，说明理由环节在秒级节奏下会被跳过——这是原型暴露出的主要设计问题。

## 闭环的第三个环节

前两个环节（可溯源、可评判）已经在跑；第三个环节（判定转成训练数据）搭好了管线，但**还没有真正训练过**。

```
复核记录 ──loop_labels.py──> cache/loop_labels.jsonl
                                    │
   近场新数据（可选，只做深度监督）──┤
                                    ▼
             ResNet18（冻结）+ LoRA(layer3/4) → DepthHead
                                    │
              ┌─────────────────────┴──────────────────┐
         掩码视差 L1                        帧级铰链（来自人的判定）
                                    │
                                    ▼
                    外部近场集验收（从不参与训练）
```

```bash
# 标签：46 条记录 -> 38 个可训练样本（含冲突标记与权重）
python scripts/loop_labels.py

# 试通：走一遍前向反向，确认接通，不保存权重
python scripts/loop_lora.py --dry-run

# 真正训练（尚未执行）
python scripts/loop_lora.py --train --epochs 10 --near-root D:/zzr/near_out2
```

两个设计决定值得说明：

**标签不绑队列条目。** `item_id` 形如 `run/episode/stem`，直接按存在性定位图像与深度，真值用 GT 深度现算。队列中途重建过，52% 的记录已不是当前队列成员，按队列查表会全部丢失；按文件定位则 46 条全部解析成功。

**冲突标签不默认可信。** 复核者判"不该触发"、而 GT 深度显示障碍在 9 米内的记录占 16%，这类标签与深度监督直接矛盾，默认权重为 0。当前 33 条有效标签与真值的一致率 82%，但其中"近场召回"只有 54%（7/13）——人对远处样本几乎全对（20/20），对近处只有一半。

LoRA 加在 layer3/layer4 的卷积上（r=8, α=16），可训练参数 1.13M，占全模型的 9%。铰链把帧级判定翻译成对 ROI 前方距离 p05 的约束：判"该触发"要求 `f ≤ 9−1.5`，判"不该触发"要求 `f ≥ 9+1.5`。

**外部验收集**是 2026-11-18 新采的 10 次近场飞行（`D:/zzr/near_out2`，1422 帧，3 米高度贴楼，前方距离中位 10.8 米），从未参与训练。现有 v4 模型在这个集上的基线：中位误差 −0.02 米、δ1 0.871，但真值 <9 米的 218 帧只召回 31 帧（**14%**）——预测几乎恒定在 11 米附近，失去了近距离的分辨能力。这是闭环需要改进的起点。

## 已知限制

- 数据全部来自仿真，缺少真实相机的噪声与光照突变
- 近场样本偏薄（留出集仅 408 帧占 12%），而它恰是失效最集中的区间
- 9 个后补近场航段未进入本轮训练
- 人在回路的闭环搭好了第三个环节的管线（LoRA + 帧级铰链），但从未真正训练，效果未知
- 复核标签规模太小：38 个样本、重复标注仅 6 对，一致性 kappa 为 0，还不足以支撑统计推断
- 界面效果没有做过用户实验
